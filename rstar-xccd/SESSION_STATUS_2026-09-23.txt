1. WHAT HAPPENED THIS SESSION
--------------------------------------------------------------------------------
a) Found and fixed a real MCTS search bug (user-reported: "when the number of
   generated nodes per step goes above 2, inference loops / doesn't
   diversify"). Root cause: rstar_deepthink/nodes/mcts_node.py puct() gave
   an unvisited child's exploration term a hardcoded 0 instead of a real
   bonus, and rstar_deepthink/agents/mcts.py select_child() broke ties by
   list order, not randomly. Together this meant a node's FIRST-listed child
   could permanently outrank all its still-unvisited siblings the moment it
   got one positive reward -- confirmed by direct simulation (old code
   picked child 0 for 8/8 rollouts; fixed code round-robins all children
   first, matching the reported symptom exactly).
   FIX (both applied, uncommitted, working tree only):
     - mcts_node.py puct(): AlphaZero-style bonus
       c_puct*sqrt(parent.visit_count())/(1+visit_count()), replacing the
       old hardcoded-0-for-unvisited branch.
     - mcts.py select_child(): restricts competition to a node's
       not-yet-visited children whenever any exist (supplementary guard on
       top of the puct() fix, requested explicitly).
   Documented as a "Technical contribution" in
   /lustre06/project/6104180/khajezad/rstar-xccd-remote/rStar-XCCD/methodology.tex
   (subsec:mcts_search), including the caveat that the supplementary guard
   becomes the binding depth constraint when iterations < n_generate_sample.
