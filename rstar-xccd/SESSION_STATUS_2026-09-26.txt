PART D -- BUGS FOUND AND FIXED THIS SESSION (details in memory + comments)
--------------------------------------------------------------------------------
D1. SPECIAL-TOKEN BUG (train/train_SFT.py, fixed ~line 317):
  The script added 17 step tags (<code>, <end_of_step>, <analysis>, ...) as
  special tokens, then resize_token_embeddings(len(tokenizer)) with no init.
  Qwen3-4B's matrix already has 151936 rows, so this SHRANK it to 151686 and
  the new ids 151669-151685 reused padding rows that are all the SAME vector
  (pairwise cosine 1.0). Embeddings are tied -> the model cannot tell the
  tags apart. Symptom: 0 code steps in every SFT checkpoint's trees, junk
  step starts ("ksiazka", <tool_call>), high no-judgment rate.
  Fix: no added tokens, no resize; tags stay plain text as at inference.
  train/train_RM.py:71 has the same pattern (not used yet -- fix before use).

D2. TRUNCATION BUG (all Qwen3/run_sft_*.sh):
  No launcher passed --model_max_length, so train_SFT.py used 2048 and
  truncated from the right (target first). trackA strict: 116/130 targets
  fully cut; hard-codenet java_rust v1: 168/168.
  Fix: all 17 launchers pass --model_max_length 8192 (covers 99.5% of
  10,161 examples; p99 7477, max 16163); train_SFT.py now DROPS over-length
  examples and logs the count instead of truncating.
  To fit 8192 tokens on 40 GB A100s: per_device_train_batch_size 2 -> 1 and
  gradient_accumulation_steps doubled (effective batch unchanged: 8, or 64
  for codenet_all/rust_only).

D3. DISK QUOTA: /project/def-khajezad hit 1000/1000 GB. Each SFT run kept a
  63 GB checkpoint-N/ dir (FSDP optimizer state). Deleted those for the 8
  old runs (their final top-level weights are kept); live quota 489/954 GB.
  All launchers now use --save_strategy "no" (final ~17 GB weights only).
