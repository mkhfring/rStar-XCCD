GOTCHAS HIT AND FIXED (all already applied in the launcher scripts as they
stand now -- re-read if resubmitting anything to confirm they're still
there):
  a) OOM with the Qwen2.5-7B-derived recipe's default eager attn_impl --
     this was NEVER a working recipe even for the original 7B model (jobs
     3081888/3121560/3138488 for q2.5-7b-sft-trackB ALL failed too, one via
     the same eager-attention OOM; SFT_DATA_PROCESS.txt's "in flight" note
     was simply never updated). Fix: --attn_impl sdpa --gradient_checkpointing True.
  b) Lost checkpoints: the launcher cd's into a node-local $SLURM_TMPDIR
     scratch dir via a symlink farm over REPO; sft_checkpoints/ didn't
     exist in REPO at symlink-farm-build time, so a RELATIVE --output_dir
     wrote the trained model to ephemeral node storage, wiped when the job
     ended. Jobs 3632724/3632727 COMPLETED with real decreasing loss but
     0 recoverable output -- confirmed lost. Fix: OUTPUT_DIR is now an
     ABSOLUTE path, "$REPO/sft_checkpoints/...".
  c) qwen3-4b-hard-v1's first successful-looking run (3632724) only did 2
     real optimizer steps (effective batch 128 >> 59-example dataset) --
     fixed by shrinking batch/grad_accum (see 2a).
